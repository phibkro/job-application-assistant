# Technical context

## Executable stack

- TypeScript 5, Bun as runtime/package manager/bundler/test runner.
- Effect v4 (`effect@4.0.0-beta.104`), pinned exactly. `../effect` is the official local Effect source and idiom guide; its checkout currently reports beta.107, so examples and APIs must be checked for compatibility with the pinned beta.104 dependency.
- `effect/unstable/httpapi` declares the API contract (`apps/worker/src/Api.ts`); it replaces a hand-kept OpenAPI document and hand-kept router agreement.
- Cloudflare D1 as the sole application persistence layer, reached through `apps/worker/src/db/`.
- `oxfmt`/`oxlint` for formatting and lint; `vitest` for tests.
- Wrangler for local `wrangler dev`/`wrangler d1` and Alchemy-driven deploy; Alchemy v2 (`infra/alchemy.run.ts`) declares the D1 database, TypeScript Worker, its bindings, and cron triggers for every stage.
- `just` as the internal command graph; `./deploy` for staging and `./deploy-production` for explicit production deployment. These commands are source-defined deployment paths, not current deployment evidence; staging evidence is stale.
- Python and curl remain for policy/credential/repo-hygiene scripts under `scripts/`; no Python or shell script builds, tests, or smokes application code anymore.

## Workspace

```text
apps/worker/src/    routes, handlers, ingestion, corpus, accounts, drafting, db
apps/web/            user interface
packages/domain/     canonical identity, normalization, matching (Effect Schema)
packages/adapters/   source connectors (NAV, JSON-LD, rendered)
infra/               Alchemy v2 infrastructure declaration
scripts/ts/          generated schema and source-catalog seed emit/check tools
db/schema.sql        generated D1 schema snapshot
db/catalog-seed.sql generated researched source-catalog seed
```

`db/schema.sql` is generated by `scripts/ts/schema.ts`; `db/catalog-seed.sql` is generated by `scripts/ts/catalog.ts` from the researched platform index and observations. `bun run schema:check` and `bun run catalog:check` detect drift.

Only NAV is registered in `apps/worker/src/runtime/Layers.ts`. `apps/worker/src/ingestion/scheduled.ts` selects the Feed tier implemented by this deployment, and `infra/alchemy.run.ts` declares only the corresponding ingestion cron. `scheduled.test.ts` guards target selection.

## Deployment and evidence

`infra/alchemy.run.ts` is the current source declaration: every Alchemy stage uses the bundled TypeScript Worker and generated schema/catalog inputs. Do not infer a live deployment from that declaration. Staging evidence is stale. Production qualification remains open: no current proof covers the realistic-corpus query-plan regression, restore drill, or black-box staging smoke path for the TypeScript service. Administrative routes and generated OpenAPI coverage are also incomplete.

`just preview` / `./scripts/preview.sh` runs the TypeScript stack locally: the Worker on workerd, the built interface beside it as static assets, and a local D1 seeded from `db/schema.sql` and `dev/preview-seed.sql`.
`scripts/deploy-preview.sh` deploys the same bundle to its own `preview` Cloudflare stage, independent of the stale staging evidence.
